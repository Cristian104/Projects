# ADR-004 — Gemini API Dual-Backend Brain

**Date:** 2026-02-25 | **Status:** Accepted | **Version:** V0.5.2-Pre

## Problem

The original Brain used local Ollama (DeepSeek-R1:14b). On laptop-class hardware, the 14b Manager takes 2–5 minutes per inference call. A full Sentinel pass of 10 candidates = worst-case 20–30 minutes per cycle. Guardian exit signals were delayed by up to 28 minutes.

## Decision

**Google Gemini API as a selectable backend** — hot-switchable at runtime via dashboard toggle.

- `google-genai>=1.0.0` added as dependency  
- `_query_model()` refactored into `_query_gemini()`, `_query_ollama()`, and a dispatcher based on `brain_mode`
- `brain_mode` stored in `bot_settings` DB table (not just env vars) for runtime switching

## Performance Impact

| Backend | Per-call time | Full cycle time |
|---------|--------------|----------------|
| Ollama (14b) | 2–5 min | 20–30 min |
| Gemini 2.5 Flash | 2–6 sec | ~2 min |

**10–15× improvement** in cycle time.

## Why Not Quantize Local Models?

4-bit quantization degrades reasoning quality on financial JSON output tasks. The Manager's strict JSON schema compliance is sensitive to quantization artefacts.

## Why Not Async Parallel Inference?

`DBManager` uses synchronous `psycopg2` — not safe for concurrent access. Refactoring to thread-safe connection pooling is out of scope.

## Consequences

✅ Full cycle time: 20–30 min → ~2 min  
✅ Local Ollama path fully preserved — no regression  
✅ Hot-switchable without restart  
⚠️ Gemini requires internet + `GEMINI_API_KEY`  
⚠️ Free-tier rate limits — heavy scans may 429  
⚠️ Network failure mid-cycle → affected tickers default to HOLD
